\begin{abstract}
Answering numerical questions over real-world corporate financial statements requires complex multi-table reasoning, fine-grained tabular disambiguation, accounting unit harmonization, and precise programmatic computation. Standard retrieval-augmented generation (RAG) approaches frequently stumble on financial benchmarks due to two fundamental challenges: (1) semantic similarity ranking cannot guarantee computational completeness when queries require multiple distinct operands (e.g., combining balance sheet liabilities with income statement revenues), and (2) unconstrained large language model (LLM) code generation regularly introduces precision degradation, unauthorized schema hallucinations, and silent unit discrepancies. In this paper, we present the core technical architecture of \textbf{FinLens}, an end-to-end Text-to-Pandas system tailored for complex financial question answering. We structure the system around an online reasoning and execution state graph featuring layered cross-encoder reranking, a two-stage table selection mechanism powered by parallel scouts and a formal \textit{Concept Coverage Matrix}, grounded execution planning with dynamic row hydration, multi-pass Abstract Syntax Tree (AST) validation, and hardware-isolated microVM sandboxed execution with complete provenance tracking. We also detail the accompanying dataset characteristics, offline extraction pipelines across four regulatory accounting domains, and the empirical evaluation protocol.
\end{abstract}

\section{Introduction}
\IEEEPARstart{Q}{uestion} answering over corporate financial statements represents a critical frontier in document understanding and natural language reasoning~\cite{chen2021finqa,zhu2021tat,islam2023financebench}. Unlike open-domain question answering, financial queries are inherently quantitative, multi-step, and bound by strict accounting standards. Users frequently ask for profitability ratios, capital structure comparisons across peer enterprises, or consolidated versus separate entity indicators.

Solving such queries over annual and quarterly disclosures presents three fundamental architectural hurdles:
\begin{enumerate}
    \item \textbf{Schema Heterogeneity \& Extraction Noise}: Corporate filings extracted from scanned PDF or HTML documents exhibit varying row label depths, note references, unit scales (e.g., raw currency vs. millions vs. billions), and non-standard tabular structures that resist rigid SQL schema assumptions.
    \item \textbf{Computational Completeness vs. Semantic Similarity}: Standard dense retrievers and cross-encoders optimize for textual relevance rather than mathematical sufficiency. A financial calculation such as $R = \frac{\text{Current Assets}}{\text{Current Liabilities}}$ requires \textit{both} accounting concepts; returning multiple redundant asset tables while omitting liabilities results in computational failure.
    \item \textbf{Code Generation Vulnerabilities}: Directly executing LLM-generated Python/Pandas logic can introduce silent precision drift from unrequested rounding, ungrounded access to metadata properties, and hazardous host execution environments~\cite{gao2023pal,chen2023pot,agache2020firecracker}.
\end{enumerate}

To overcome these challenges, \textbf{FinLens} adopts a neuro-symbolic Text-to-Pandas paradigm that pairs modern language models with deterministic compile-time and run-time guardrails. In this paper, we document the system's end-to-end architecture, dataset foundation, and evaluation framework.

\section{System Architecture \& Online Inference}
The FinLens online execution pipeline is formalized as an \textbf{Agentic StateGraph} state machine. The global execution context is governed by an immutable typed state container $\mathcal{S}$ (\texttt{RetrievalState}) containing the canonical user question $q$, active metadata filters $\mathcal{F}$, candidate table collections at progressive stages of distillation, isolated table DataFrames $\mathcal{D}$, planning context $\mathcal{P}$, generated code syntax $\mathcal{C}$, attempt counters, and execution feedback diagnostics.

As shown in \Cref{fig:system_topology}, the architecture decouples specialized LLM reasoning agents from deterministic tools and execution environments across eight distinct stages:
\begin{equation}
\begin{aligned}
    q &\xrightarrow{\text{Upstream}} \mathcal{T}_{80} \xrightarrow{\text{Rerank}} \mathcal{T}_{20} \xrightarrow{\text{Select}} \mathcal{T}^* \\
      &\xrightarrow{\text{Load}} \mathcal{D} \xrightarrow{\text{Plan}} \mathcal{P} \xrightarrow{\text{Synthesize}} \mathcal{C} \underset{\text{Retry}}{\overset{\text{Execute}}{\rightleftharpoons}} \mathcal{A}
\end{aligned}
\end{equation}
where $\mathcal{T}_{80}$ represents the top candidates from upstream hybrid retrieval, $\mathcal{T}_{20}$ denotes the cross-encoder reranked subset, $\mathcal{T}^*$ represents the minimal exact evidence tables, $\mathcal{D}$ denotes loaded memory-isolated DataFrames, $\mathcal{P}$ is the hydrated planning context, $\mathcal{C}$ is the validated AST-normalized Python script, and $\mathcal{A}$ is the verified final answer record.

\subsection{Query Routing \& Hybrid Retrieval}
Incoming queries are processed by a Query Router Agent that validates ticker symbols, reporting years (restricted to the canonical 2015--2025 window), and disclosure scopes (\textit{consolidated}, \textit{separate}, \textit{aggregated}). Candidate tables are retrieved using a hybrid strategy combining dense embedding search with BM25 lexical matching via Reciprocal Rank Fusion (RRF)~\cite{cormack2009reciprocal,robertson2009probabilistic} to produce a balanced pool of up to 80 candidate tables $\mathcal{T}_{80}$.

\subsection{Cross-Encoder Reranking \& Context Packaging}
To refine the initial candidate pool, FinLens deploys a multilingual cross-encoder reranker based on BGE-M3~\cite{chen2024bge}. Because full tabular CSVs exceed standard token windows, FinLens builds a layered contextual representation for each candidate table:
\begin{itemize}
    \item \textbf{Structural Header \& Metadata}: Extracted titles, reporting years, and column names.
    \item \textbf{Complete Row Catalog}: A lightweight index mapping all row indices to standardized accounting line codes and normalized labels without truncation.
    \item \textbf{Lexical Seed \& Neighbor Expansion}: Seed rows matching question tokens are expanded with immediate vertical neighbors $(r-1, r, r+1)$ to preserve subtotals and subsection hierarchy.
    \item \textbf{Bounded Serialization}: High-signal match summaries are packed into a bounded document ($\le 6,000$ characters) for cross-encoder scoring, yielding the top 20 finalist tables ($\mathcal{T}_{20}$).
\end{itemize}

\subsection{Two-Stage Table Selection with Concept Coverage}
To guarantee mathematical completeness, FinLens implements a two-stage selection mechanism governed by an explicit \textit{Concept Coverage Matrix} (\Cref{fig:table_selection}):
\begin{enumerate}
    \item \textbf{Parallel Scouting}: The 20 candidates are partitioned into balanced chunks across document buckets (ticker and year pairs), and two parallel LLM scouts nominate all candidates capable of providing at least one required operand.
    \item \textbf{Lexical Rescue}: An out-of-band filter bypasses scout pruning for candidates containing exact multi-word indicator phrases from the question.
    \item \textbf{Concept Coverage Arbiter}: The arbiter decomposes the question into financial concepts with explicit computational roles $\rho \in \mathcal{R}_{\text{roles}}$:
    \begin{equation}
        \mathcal{R}_{\text{roles}} = \left\{
        \begin{array}{l}
            \text{direct}, \, \text{numerator}, \, \text{denominator}, \\
            \text{beginning\_balance}, \, \text{ending\_balance}, \\
            \text{comparison\_operand}
        \end{array}
        \right\}
    \end{equation}
    Each concept must be bound to a candidate table covering the indicator. The arbiter enforces that no concepts remain uncovered, no orphan tables are selected, and multi-year/multi-ticker comparative buckets are structurally preserved. A correction sub-loop intercepts and fixes validation deficiencies within one attempt.
\end{enumerate}

\subsection{Grounded Planning \& Dynamic Row Hydration}
Approved tables $\mathcal{T}^*$ are loaded into memory as isolated DataFrames $\mathcal{D} = \{ \text{df}_1: \mathbf{D}_1, \dots, \text{df}_m: \mathbf{D}_m \}$. A Planning Agent generates a four-field structured plan (\textit{evidence}, \textit{calculation}, \textit{unit\_conversion}, \textit{audit}) declaring exact row positions and operational purposes. If catalog rows outside the initial detailed preview are referenced, FinLens dynamically \textit{hydrates} their full numerical values from disk on demand, ensuring complete data access without prompt bloat.

\subsection{AST-Governed Code Synthesis \& Multi-Pass Guardrails}
The Code Synthesis Agent emits structured Python/Pandas logic $\mathcal{C}_{\text{raw}} = \{ \text{"pandas\_query"}: \text{str}, \, \text{"evidence\_variables"}: [\text{str}] \}$. Before execution, the code is parsed into an Abstract Syntax Tree (AST) and processed through an 8-pass normalization pipeline (\Cref{tab:ast_passes} and \Cref{fig:synthesis_and_sandbox}):
\begin{itemize}
    \item \textbf{Syntax \& Scalar Normalization}: Enforces parseable Python syntax and automatic assignment of the final scalar to \texttt{result}.
    \item \textbf{Selector \& Unit Alignment}: Canonicalizes boolean filter literals (e.g., \texttt{'10.0'} $\rightarrow$ \texttt{'10'}) and automatically normalizes currency divisors ($10^6, 10^9, 10^{12}$) based on cell magnitudes.
    \item \textbf{Security \& Precision Guards}: Intercepts and blocks unauthorized `.round()` invocations, ungrounded access to DataFrame metadata attributes (\texttt{df.metadata} / \texttt{df.attrs}), and improper ratio/difference formulas.
\end{itemize}

\subsection{Sandboxed MicroVM Execution \& Dual-Layer Retries}
Validated code is executed inside ephemeral Firecracker microVMs managed via E2B~\cite{agache2020firecracker}, with network access disabled (\texttt{allow\_internet\_access = False}) and a 5.0-second execution timeout. Results are extracted through a bounded two-step serialization protocol writing a verified scalar JSON payload ($\le 1,024$ bytes) to disk.

The system incorporates a dual-layer fault-tolerance model:
\begin{enumerate}
    \item \textbf{Transient Retries}: Network and API hiccups are handled automatically by node-level retry policies without consuming semantic reasoning attempts.
    \item \textbf{Semantic Retries}: AST validation rejections and runtime microVM exceptions are converted into structured diagnostic feedback and routed back to the Code Synthesis Agent (up to a configurable attempt limit $1 \le \text{max\_attempts} \le 5$).
\end{enumerate}

\subsection{Answer Provenance Assembly}
Upon successful execution, FinLens constructs an immutable \texttt{answer\_record} that binds the final numeric answer to the original PDF document ID, the table start line within the document, the underlying CSV path, and the exact reproducible Pandas query.

\subsection{Offline Document Ingestion \& OCR Table Extraction}
The raw inputs consist of multi-page scanned PDF filings and HTML corporate disclosures. An offline extraction pipeline performs document inventorying, layout analysis, optical character recognition (OCR), table boundary detection, and cell normalization. Extracted tables are converted into structured CSV files with standardized column names (\texttt{row\_label\_raw}, \texttt{item\_label\_norm}, \texttt{item\_code}, \texttt{note\_title}, and reporting period headers).

\subsection{Regulatory Domain Classification \& Taxonomy Induction}
Vietnamese accounting regulations prescribe distinct chart-of-accounts frameworks depending on the corporate entity type:
\begin{itemize}
    \item \textbf{General Enterprises (\textit{Doanh Nghiep - DN})}: Governed by Ministry of Finance Circular 200/2014/TT-BTC.
    \item \textbf{Credit Institutions \& Commercial Banks (\textit{To Chuc Tin Dung - TCTD})}: Governed by Circular 49/2014/TT-NHNN.
    \item \textbf{Securities Companies (\textit{Cong Ty Chung Khoan - CTCK})}: Governed by Circulars 210/2014/TT-BTC and 334/2016/TT-BTC.
    \item \textbf{Insurance Enterprises (\textit{Bao Hiem - BH})}: Governed by Circular 232/2012/TT-BTC.
\end{itemize}
The offline pipeline automatically classifies each entity into its respective regulatory regime and induces hierarchical accounting taxonomies to map heterogeneous OCR labels to canonical financial concepts.

\subsection{Hybrid Vector Indexing}
Each normalized table is indexed into a hybrid vector store (Qdrant) utilizing dense embeddings alongside BM25 sparse indices, with payloads carrying ticker, fiscal year, disclosure type, regulatory domain, and induced accounting taxonomy tags.

\section{Experiments \& Benchmark Evaluation}

\subsection{Experimental Setup \& Metrics}
Evaluation is conducted across three primary quantitative metrics:
\begin{itemize}
    \item \textbf{Answer Accuracy (\%)}: Percentage of questions where the executed numerical result matches the ground-truth answer within a strict numerical tolerance ($\le 0.1\%$).
    \item \textbf{Execution Success Rate (\%)}: Percentage of queries where the generated Pandas code successfully compiles and executes without sandbox exceptions.
    \item \textbf{Evidence Retrieval $F_2$ Score}: Macro-averaged $F_2$ measure over retrieved and selected table identifiers, emphasizing recall of all necessary calculation operands.
\end{itemize}

\subsection{Error Analysis}
A qualitative error audit categorizes residual failure modes into four primary types: (1) OCR extraction truncation on degraded filings, (2) subtle ambiguous footnotes requiring unstated accounting assumptions, (3) timeout exceptions on extremely large multi-table aggregations, and (4) edge-case unit confusion on non-standard disclosures.

\section{Discussion \& Limitations}
The architectural design of FinLens offers several practical takeaways for enterprise financial AI systems:
\begin{itemize}
    \item \textbf{Expressiveness of Text-to-Pandas}: While relational SQL is suited for structured databases, Pandas provides superior flexibility for OCR-extracted tables with variable row depths, multi-index labels, and complex non-linear arithmetic.
    \item \textbf{Pre-Execution Semantic Verification}: Static AST validation and automatic scale normalization eliminate common LLM calculation errors without incurring costly additional LLM roundtrips.
    \item \textbf{Limitations}: The system relies on accurate OCR tabular segmentation and is benchmark-scoped to quantitative financial statement question answering.
\end{itemize}

\section{Conclusion}
In this paper, we presented the technical architecture of FinLens, an end-to-end Text-to-Pandas system for numerical question answering over financial statements. By combining layered cross-encoder reranking, concept-coverage table selection, grounded context planning, multi-pass AST normalization, and hardware-isolated sandboxed execution, FinLens provides reliable, mathematically sound, and fully auditable numerical reasoning over complex financial tables.
